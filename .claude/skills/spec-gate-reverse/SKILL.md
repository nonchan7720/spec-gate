# spec-gate reverse をサブエージェントに委譲する

spec-gate は LLM を呼ばない。逆変換は 2 段階で、どちらも claim ごとに独立した判断にする。

- 再生成（restate）: claim の内容だけから仕様文を書き起こす。元の仕様は見せない
- 比較（compare）: 再生成した文と元の仕様を突き合わせる

再生成の担当が元の仕様や他の claim を見てしまうと、食い違いを見つけられなくなる。
そのため **プロンプト 1 つにつき新しいサブエージェント 1 体**に、互いの答えを見せずに答えさせる。
あなた（オーケストレーター）の仕事は、プロンプトを配って回答を集めることだけで、判断の中身には関わらない。

## 手順

1. 再生成のプロンプトを書き出す

   ```sh
   spec-gate reverse [<claim-id>...] --emit
   ```

   stdout にプロンプトファイルの絶対パスが 1 行に 1 つ出る（`.spec-gate-llm/reverse/<claim-id>.restate.prompt.md`）。
   各ファイルは自己完結していて、ルール・claim・回答ファイルのパスをすべて含む。

2. プロンプト 1 つにつき、新しい `spec-gate-llm-worker` サブエージェントを 1 体起動する。全員を並列に（1 つのメッセージでまとめて）起動する。
   各サブエージェントに渡すタスクのメッセージは、次の 1 文だけにする。

   ```
   Read <プロンプトファイルの絶対パス> and follow it.
   ```

   全員が終わるのを待つ。

3. 再生成の回答を取り込み、比較のプロンプトを書き出す

   ```sh
   spec-gate reverse --collect
   ```

   stdout に比較のプロンプトのパス（`<claim-id>.compare.prompt.md`）が出る。

4. 比較のプロンプトについて、手順 2 と同じことをする。再生成を担当したワーカーは使わず、**すべて新しいワーカー**にする。

5. 比較の回答を取り込み、レポートを出す

   ```sh
   spec-gate reverse --collect            # mismatch / error で exit 1 にしたいときは --strict
   ```

   レポートを出すと作業ディレクトリは消える。

どの collect でも、回答が欠けていれば欠けている claim と段階（例: `ROUND-001.restate`）と回答ファイルのパスを挙げてエラーになる。
そのプロンプトだけを **新しい** `spec-gate-llm-worker` 1 体に同じ 1 文で渡し直してから、もう一度 collect する。
emit で表示されるプロンプトが 0 件なら（すべて skipped など）、そのまま collect するとレポートが出る。

## 守ること（判断の独立性）

- ワーカーへのメッセージに、自分の指示・要約・解釈・ヒント・仕様や claim の説明・他の claim の結果を**足さない**。「Read <path> and follow it.」だけを渡す
- ワーカーを使い回さない。**1 体 = 1 プロンプト**。段階が変わっても、再試行でも、必ず新しいワーカーにする
- `spec-gate-llm-worker` 以外のエージェント（ツールの多い汎用エージェントや fork）に答えさせない
- プロンプトファイルや回答ファイルを自分で読んだり書いたり直したりしない。回答が壊れていたら、そのプロンプトを新しいワーカーでやり直す
- reverse の結果はレビュー補助で、承認ではない。食い違いがあれば人間に伝える（claim を直すときは `claims/_pending/` に修正案を置く）
