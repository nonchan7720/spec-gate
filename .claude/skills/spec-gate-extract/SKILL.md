# spec-gate extract をサブエージェントに委譲する

spec-gate は LLM を呼ばない。抽出は N 回の独立した判断の一致（合議）で信頼度を決めるので、
**各 run を別々の、新しいサブエージェントに、互いの答えを見せずに**答えさせる。
あなた（オーケストレーター）の仕事は、プロンプトを配って回答を集めることだけで、抽出の中身には関わらない。

## 手順

1. プロンプトを書き出す

   ```sh
   spec-gate extract <ref> --runs N --emit        # mermaid などは --type も付ける
   ```

   stdout にプロンプトファイルの絶対パスが 1 行に 1 つ出る（`.spec-gate-llm/extract/<ref の名前>/run-<k>.prompt.md`）。
   各ファイルは自己完結していて、ルール・仕様の抜粋・その run の回答ファイルのパスをすべて含む。

2. プロンプト 1 つにつき、新しい `spec-gate-llm-worker` サブエージェントを 1 体起動する。全員を並列に（1 つのメッセージでまとめて）起動する。
   各サブエージェントに渡すタスクのメッセージは、次の 1 文だけにする。

   ```
   Read <プロンプトファイルの絶対パス> and follow it.
   ```

3. 全員が終わるのを待つ。

4. 回答を取り込む

   ```sh
   spec-gate extract <ref> --collect
   ```

   合議の結果が `claims/_pending/` に置かれ、作業ディレクトリは消える。
   回答が欠けていると、欠けている run と回答ファイルのパスを挙げてエラーになる。
   その run のプロンプトだけを、**新しい** `spec-gate-llm-worker` 1 体に手順 2 と同じ 1 文で渡し直してから、もう一度 collect する。

## 守ること（合議の独立性）

- ワーカーへのメッセージに、自分の指示・要約・解釈・ヒント・仕様の説明・他の run の結果を**足さない**。「Read <path> and follow it.」だけを渡す
- ワーカーを使い回さない。**1 体 = 1 プロンプト**。2 つ目のプロンプトは必ず新しいワーカーに渡す（再試行も新しいワーカー）
- `spec-gate-llm-worker` 以外のエージェント（ツールの多い汎用エージェントや fork）に答えさせない
- プロンプトファイルや回答ファイルを自分で読んだり書いたり直したりしない。回答が壊れていたら、その run を新しいワーカーでやり直す
- 別の ref の回答を流用しない（collect は ref ごとのディレクトリからしか読まない）
- collect の結果は承認ではない。承認は人間が `spec-gate review` / `approve` で行う
